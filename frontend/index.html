Chrome Extension Feature

Live Perception

SightLite's perception engine runs entirely on your device using an ONNX model (or a DOM-based fallback). It captures your screen and identifies interactive elements in real time — buttons, inputs, links, and more.

How to use Live Perception
1

Load the extension in Chrome

Go to chrome://extensions → Enable Developer mode → Click Load unpacked → Select the extension/ folder from this project.

2

Navigate to any webpage

Open Chrome and go to any website you want to interact with — e.g. google.com, a form page, or a dashboard.

3

Open the SightLite side panel

Click the SightLite icon in your Chrome toolbar. The side panel opens on the right. If you don't see it, right-click the icon → Open side panel.

4

Type a goal and press "Run agent"

SightLite captures your screen, perceives all UI elements, plans steps, and executes them. Results appear here in the dashboard under History.

How perception works
🧠

ONNX Model (when available)

If you place uidet.onnx in the models/ folder and ort.min.js in lib/, the extension runs on-device inference to detect UI elements visually from a screenshot.

🔍

DOM Fallback (default)

Without the ONNX model, SightLite scans the DOM for button, input, a, and other interactive elements. Works on any page out of the box.

🔒

Fully On-Device

No data is sent to any server. All inference happens in the browser via WebGPU or WASM. Your screen captures never leave your machine.

📡

Local Backend Only

Session metadata (goals, frames, actions) is saved to the local PostgreSQL database at localhost:8000. This is the dashboard you're looking at right now.

📸 Extension Feature

Screen Analysis

Every time the agent runs a step, it captures the visible tab as a JPEG screenshot and scans for interactive elements. This data is stored locally so you can review what the agent perceived.

What gets captured per frame
1

Screenshot

The visible tab is captured at 70% JPEG quality via chrome.tabs.captureVisibleTab. This is sent to the offscreen document for ONNX inference.

2

Element Detection

The ONNX model (or DOM scanner) returns a list of detected UI elements with bounding boxes, labels (button, input, link, etc.), and confidence scores.

3

Frame saved to database

Each frame's latency and up to 60 detections are POSTed to localhost:8000/sessions/:id/frames and stored in PostgreSQL. View them in the History tab.

⚡ Automation

Automate Tasks

SightLite uses a rule-based planner to break down your goal into steps. Each step is one of: click, type, or scroll. Chain them with then.

Command syntax
Actions you can use
👆
click <element> — clicks the element matching that label or text
⌨️
type "text" in <element> — focuses an input and types the value
📜
scroll — scrolls down 80% of the viewport height
🔗
Chain steps with then: type "hello" in search then click go
Example goals
✦

Search for something

type "OpenAI" in search then click Search

✦

Fill a form and submit

type "John" in name then type "john@example.com" in email then click Submit

✦

Scroll and click

scroll then click Learn more

💡
Tip Element matching is fuzzy — SightLite looks for elements whose visible text or aria-label contains your keyword (case-insensitive). Be specific if a page has multiple similar elements.
